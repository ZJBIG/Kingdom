# Kingdom 任务交接

## 任务与状态

填写用户授权目标、只读/实施范围、当前完成与未完成部分。续写已有同主题报告；不要因新会话创建脱节副本。

## 起始状态与保留工作

记录起始 commit、相关工作区变更与并行新增文件。列出本任务拥有的文件，不把他人工作纳入本次修改。

## 文件与行为变更

逐项说明路径、修改原因、行为前后；经济定义填写具体字段前后值与受影响依赖。ID/GUID/序列化变化必须单列授权与迁移证据。

## 验证执行

逐项记录命令、时间、退出码、输入版本/指纹、XML/log路径、项目用例数与通过/失败/跳过。将静态检查、模拟器fixture诊断和 Unity 运行分栏。外部运行体验由用户自行验收，代理不执行或跟踪；若未运行Unity，注明“未执行真实 Unity 编译。”

## 风险与证据限制

列出未复现/未覆盖的行为、旧文档冲突、依赖或项目占用限制。不得把历史结果或零用例说成验收。

## 下一具体行动

给出下一位执行者可以直接开始的文件、复现条件或验证命令。若需要用户确认，写清确认事项；不要把整个旧计划机械复制为待办。
