# 子代理并行与复核协议

对全仓扫描、跨模块缺陷或多项独立验证，启用独立子代理。不要为只读一个文件增加调度成本。支持并行时同轮派发互不依赖的工作；实际不支持或启动失败时缩小范围或由主代理顺序接管，不重复等待。

## 默认分工

| 角色 | 范围 | 必交结果 |
|---|---|---|
| 运行时/存档 | 自有 Manager、Runtime、Math、Validation | 调用链、强类型入口、事务与时间顺序、精确路径证据 |
| 内容/UI | Datas、Scene/Prefab、UI、相关领域技能 | 定义关系、加载路径、资产/代码偏差、运行待验证项 |
| 工具/测试 | tools、测试程序集、当前摘要、相关 handoff | 真实参数、副作用、测试选择、证据时效与缺口 |
| 独立复核（实现之后） | 本轮 diff、指定测试与交付范围 | 是否越权、是否有反射、引用是否存在、验收是否诚实 |

仅在涉及该领域时派发该角色。给每个角色明确根路径、只读/写入权限、排除目录、已有发现、要解决的问题与输出上限。不要让子代理自行发散修复。

## 可复用任务简报

```text
目标：为 Kingdom 的 [具体问题] 提供事实与验证建议。
根路径：已确认的项目绝对路径。
权限：只读；禁止写入、安装、启动 Unity、改变资产和个人存档。
先读：根与 scoped AGENTS、相关当前 handoff；源码高于历史报告。
范围：明确目录/文件。排除 Library、.git、bin/obj、归档和第三方实现。
问题：复现条件、状态所有者、调用链、最小受影响面、测试与副作用。
交付：准确路径/行号/方法；事实与推测分开；列出未运行验证。
限制：不要把时间戳旧报告视为当前证据；不要提出未经授权的大规模重构。
```

## 主代理责任

1. 独立核对影响实施决策的关键结论：读取实际文件和公共方法，核对 GUID/字段，不能仅复述代理摘要。
2. 对有冲突的结论同时展示“文档契约”和“源码实际”，再确定本任务如何遵守；不由任何代理静默降低要求。
3. 在明确理解根因和修改范围后才分配代码写入。划定互斥文件所有权；同一文件只允许一个执行者写。
4. 子代理完成后检查真实 diff 和验证输出，排除越界修改；记录完成的分工，不声称失败的代理已完成。
5. 失败时说明已接管的范围；不得伪造并行结果。未完成的任务不能标记通过。
6. 实施任务或已获写入报告授权时，将唯一综合结论写入本任务交接；纯只读任务只在回复汇总。不要让每个子代理新建互相脱节的报告。
