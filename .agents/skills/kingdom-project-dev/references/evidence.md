# 证据分级与差异处理

## 只保留一种事实身份

- **约束**：根/scoped AGENTS及领域技能规定应达到什么，不表示现有代码已经达到。
- **静态事实**：本轮读到的定义、方法、GUID和测试声明；不能证明运行行为。
- **本轮执行结果**：命令、时间、输入版本、退出码、XML/log及覆盖范围齐全。
- **历史背景**：旧审计、日期XML、pacing、归档、早期Kingdom材料，只作为待复核线索。

当前摘要入口与保留策略遵守根AGENTS；名字包含Latest也要核对时间和输入。没有文件就是缺口，不补为通过。不要在长期规则中保存易过期的“当前通过/失败数”。

## 代码与文档不一致时

1. 同时引用实际代码和文档契约，判断是过期叙述、未实现目标还是待复现问题，不直接认定bug。
2. 当前实现事实以源码/资产为准；安全和验收门槛不因源码尚未满足而降低。
3. 修改必须落在授权范围；记录未处理差异，不扩大为重做基础系统。
4. 缺参考文件时声明缺失，不声称已读取；参数与目标框架看脚本/csproj而非过期README。
5. 研究节点数、参考路径和布局事实统一看UI技能；Pair资产/运行时差异查 `docs/repository-map.md`；不在此再维护副本。

## 技能与工具审查

检查主文档及全部references/assets/helper/test，不能只看frontmatter。没有专用审查能力时披露采用人工/静态检查，不伪称认证。

- P0：凭据外传、破坏性操作、提权绕过或未审查下载执行；停止并明确警告。
- P1：隐蔽写入、无界路径、默认访问个人存档、自动安装/迁移或伪造验收；先修复复审或等待明确授权。
- P2：权限必要、边界清晰且通过检查；不代表保证无漏洞。

技能文案不是自动许可。规范包不夹带用户文件、日志、凭据或外部二进制；项目集成包仅含明确列出的规则和自有辅助源码。涉及测试fixture时除单测成功，还必须验证隔离目录真正消失；残留不能被隐藏的成功摘要掩盖。
