# Kingdom 大清洁 · 统一审查准则（只读阶段）

目标：为一个 Unity 2022.3.62f3c1 项目（根目录 `D:\GitHub\Kingdom`）做"找脏"盘点，**本阶段只识别、不修改**。

## 铁律

1. **只读**。除写自己的报告文件外，不创建/修改/删除/重命名/移动任何项目文件。
2. **不运行 Unity、不跑测试、不执行 build**。可运行只读命令：`git log`/`git show`/`git grep`、`rg`/`grep`、`find`、`ls`、`wc`、Python 只读脚本。
3. **不碰** `.git/`、`Library/`（6.6G 缓存）、`Logs/`、他人工作树改动。
4. 当前工作树有 40+ 未提交改动（含并行任务），**以当前磁盘上的文件为事实基准**，不要拿历史文档/旧审计去推翻当前源码。
5. 区分"陈旧"与"正在使用中"。凡被当前代码/场景/定义/文档引用的，一律判为"在用"，不列入清理清单。

## 判定维度（每个受审对象逐条过）

- **D1 引用失效**：文档/脚本/代码引用了已不存在的文件、目录、类型、字段、API。（已知历史坑：`CONTENTADVISE/` 目录已在 HEAD `a85f0e7` 删除，但多处文档仍引用）
- **D2 已被取代**：同一职责存在新旧两套（旧函数/旧类/旧脚本/旧文档），旧的那套已无调用点。
- **D3 历史快照**：一次性审计报告、日期命名的产出物、过期测试结果、归档包、中间产物。
- **D4 构建/缓存产物**：`bin/`、`obj/`、`.dll`、`.pdb`、`.cache`、Unity 导入缓存、burst 调试信息。
- **D5 孤儿资产**：`.meta` 无对应文件、文件无 `.meta`、资源无任何引用点。
- **D6 长期挂起的 TODO/FIXME/HACK/XXX/OBSOLETE** 注释与 ToDoList 条目（对照当前实现看是否已解决）。
- **D7 与硬约束冲突**：新增代码/测试使用反射（`System.Reflection`、`BindingFlags`、`Activator`、`Invoke`）；UI 运行时硬编码层级/尺寸/文案；普通资源（除 Food）出现容量上限/MaxAmount/仓储截断；残留 workforce 概念。
- **D8 内容重复**：同一内容在多处文档重复维护（规则应只在一处权威来源）。
- **D9 死代码/未使用**：未被引用的 public 方法、空壳类、`#if` 永久关闭分支、注释掉的大段代码。
- **D10 定义资产陈旧**：占位值、被定义表/代码/场景均不引用的定义、字段与当前 Data 类不匹配。

## 报告格式（每个受审对象一行条目）

```
- [置信度 High/Med/Low] `相对路径` — 维度 D?；证据：<具体行号/引用/对比结果>；建议：<归档|删除|更新|合并|保留观察>；理由：<一句话>
```

## 报告结构（写入指定文件）

1. 范围：你实际审查了哪些路径、多少文件（真实数字）
2. 结论清单：按"建议归档 / 建议删除 / 建议更新 / 建议合并 / 保留观察"分组
3. 不确定项：无法判定、需要用户决策的
4. 未覆盖项：因体积/二进制/第三方而跳过的（TextMesh Pro、Library 等第三方不算项目代码）

## 纪律

- 不写流水账，不把"文件存在"当问题。
- 每条必须有证据（行号、grep 命中、git log 时间戳、对照文件路径）。
- 没发现问题的区域直接写"未发现"，不凑数。
- 不要提出"重建系统"级建议；只报陈旧与冗余。
