## 2. 用户已锁定的设计决策

以下决策优先于旧审计和旧策划：

1. Food 是唯一允许有库存容量的资源。不得给普通资源增加仓库、容量或隐性 Clamp。
2. 新游戏基础食物产量为 `+5/s`。
3. 人口食物消耗固定为：

   `人口食物消耗 = 当前人口 × 1/s`

4. 食物不足时所有建筑使用同一个供给比例：

   `建筑效率食物因子 = clamp(食物潜在生产 / 食物总消耗, 0, 1)`

   食物归零不再直接让所有建筑产量瞬间归零；有持续食物生产时建筑可以按比例运行并自行恢复。
5. 玩家层面只保留“人口”和“生产力”，彻底删除“劳动力”概念。
6. 生产力采用混合来源：

   `总生产力 = 当前人口 + 科研固定加成 + Σ(建筑数量 × 建筑固定生产力加成)`

   `已用生产力 = Σ(建筑数量 × 建筑生产力消耗)`

   `可用生产力 = max(0, 总生产力 - 已用生产力)`

7. 科研和建筑提供的固定生产力不乘建筑效率，避免“缺粮→效率下降→生产力下降→进一步停产”的递归崩溃。
8. 生产力建筑不能在同一笔建造事务中用自己的加成支付自身消耗；必须按建造前的可用生产力验资。
9. 住房只提供人口上限，不直接提供生产力；住房容量也不因建筑效率下降而消失。
10. 若已用生产力超过总生产力，保留现有建筑并将可用生产力视为 0，禁止继续建造消耗生产力的建筑。
11. 不需要旧存档兼容。存档格式直接升至 v4，旧版本必须拒绝加载。

后续 AI 不得重新引入：

- `AvailableWorkforce`
- `TotalWorkforce`
- `AssignedBuildingWorkforce`
- `AssignedMilitary`（人口子系统）
- `WorkforceConsumption`
- `WorkforceInsufficient`
- 可变或存档化的 `FoodPerPerson`

军事系统继续使用独立的 `MilitaryManpower`。

## 3. 对话与实施演进

### 3.1 初始问题：进度软卡

最初模拟显示从 Animal 推进到 Medieval 约需 22.9 小时。用户随后给出了 Animal → Neolithic → Medieval 数值与进度重整策划，主要目标为：

- 首项研究 60–90 秒；
- 均衡策略 60–90 分钟进入新石器；
- 均衡策略 5–8 小时进入中世纪；
- 前 10 分钟至少完成两项研究并解锁生产建筑；
- 修复铜、锡、铁、黏土、纤维等生产链；
- 建立研究力建筑成长和等比建筑成本；
- 统一独立模拟器与 Unity 确定性模拟器。

当前工作区中与该批次有关的资产、迁移器、测试和报告均未提交。不得覆盖或回退。

### 3.2 食物规则修订

用户指出人口出生后食物会迅速归零，因此锁定：

- 新游戏 Food 基础流量 `+5/s`；
- 食物短缺按供需比例缩放全部建筑产量；
- 食物生产建筑在库存为零时仍能按供给比例工作，不能形成永久零产出死锁。

### 3.3 人口、劳动力、生产力概念收敛

用户认为人口、劳动力、生产力三个字段维护成本过高。最终选择：

- 保留人口、住房和食物意义；
- 删除劳动力；
- 人口提供基础生产力；
- 研究和组织/治理建筑提供固定生产力，承担后期扩张；
- HUD 只展示人口和生产力。

### 3.4 存档边界

原计划曾考虑读取旧存档，但用户明确否决。最终实现不得包含 v3→v4 迁移或遗留字段兼容分支。

## 4. 当前实现事实

### 4.1 人口状态

`PopulationState` 当前只拥有：

- `population`
- `populationCapacity`
- `growthProgress`

人均食物消耗为固定规则 `PopulationState.FoodConsumptionPerPerson == 1`，不再是运行时可变字段。

### 4.2 生产力

`BuildingManager` 对外提供：

- `TotalProductivity`
- `UsedProductivity`
- `AvailableProductivity`

这些值完全由人口、已完成研究效果和建筑数量派生，不写入存档，也没有提交/回滚式分配状态。

建筑建造流程：

1. 验证时代、研究和工坊前置；
2. 验证领土；
3. 用建造前的 `AvailableProductivity` 验证本批次 `ProductivityConsumption`；
4. 验证并支付资源；
5. 只向 `GameState` 提交领土占用；
6. 修改建筑数量后，新的固定生产力加成才进入总量。

拆除只退还领土并按现有规则返还资源，不修改人口字段。

### 4.3 食物与效率

新游戏基础值：

- `FoodAmount = 300`
- `FoodCapacity = 500`
- `BaseFoodProductionRate = 5/s`

人口和建筑食物消耗共同进入总需求。建筑效率使用统一食物满足率，并继续与资源、电力和物流满足率相乘。

固定生产力和人口容量按建筑数量计算，不按效率计算。

### 4.4 UI 和术语

HUD 当前展示：

- 人口：当前值 / 上限
- 生产力：可用值 / 总值
- 研究力

运行时代码、资产、Prefab 和场景扫描未发现玩家可见的“劳动力”或 `Workforce` 残留。测试中的 `DoesNotContain` 字符串仅用于防止遗留字段重新进入存档。

### 4.5 存档

- `SaveFormat.CurrentVersion = 4`
- 新存档只保存人口、人口上限和增长进度。
- 不保存生产力、已用生产力、人口军事分配或人均食物。
- `SaveManager` 仍只接受与 `CurrentVersion` 完全相等的版本。
