- 当前共有 35 个 Resource、15 个 Building、28 个 Research。
- Building 分布：原始时代 6、新石器时代 9、中世纪及以后 0。

[内容层面的关键事实]
- 从新游戏静态推演，当前只能完成 13/28 项研究，技术等级停留在原始时代。
- PlantFiber 没有任何生产建筑，TextileCraft 无法支付。
- Clay 没有任何生产建筑，Pottery 无法支付。
- CopperOre、IronOre、TinOre 没有对应矿井，冶炼线无法开始。
- SmithingRevolution 的 TechLevel 为 Medieval，但 AdvancesTechLevel=false，即使未来完成也不会推进到中世纪。
- 当前没有任何中世纪建筑。
- 35 个资源中只有约 13 个进入现有来源/消耗/建造/科研关系，22 个资源暂时没有实际循环。
- GameBootstrap 仍在启动末尾直接 AddResource(Gold)，属于调试残留。
- TinOre 的中文 Label 当前是“锌矿石”，但 ID、冶炼炉和后续用途都按锡处理，应改为“锡矿石”。
- Agriculture 当前不解锁建筑；Farm 反而由 WaterManagement 解锁。
- AnimalHusbandry 在原始时代解锁 TechLevel=Neolithic 的 Pasture，而 TryBuild 没有统一建筑时代验证。
- PotteryKiln 和 WeavingWorkshop 当前没有产出 Pottery/Cloth，内容上是空壳建筑。
- StoneTool 资源存在，但当前没有生产建筑和主要用途。
- 当前 Smithing 研究要求 CopperOre，然而 CopperMine 不存在，形成不可达内容。
- Smithing_Bronze 当前没有消耗 Tin/Tin ingot，青铜配方语义不完整。

[数值层面的关键事实]
- 新游戏只有 WoodLog +1/s。
- 初始 FoodAmount=10000、FoodCapacity=10000，早期 Granary +5000 基本没有存在感。
- 初始 AvailableSpace=100000，而建筑 SpaceCost 约 1~12，领土在早期完全不是约束。
- 初始 AvailableProductivity=100，而早期建筑消耗约 2~28，劳动力/生产力约束偏弱。
- 当前建筑材料成本完全线性；在“普通资源无上限”的前提下，长期会出现极强滚雪球。
- ExpantaNumExtensions 已经有 GeometricSeriesCost 和 MaxAffordableGeometricSeries，但建筑系统尚未使用。
- 原始时代研究 BaseCost 多为 1200~10000；研究速度默认约 1/s，对新玩家意味着单项 20~167 分钟。
- SmithingRevolution BaseCost=1e8，在 1/s 下约需 3.17 年，且当前没有研究力建筑。
- 当前 FoodAmount 到 0 后主要只是显示为 0，尚未形成清晰的劳动力/人口/建筑效率后果。
- GameState.AdvanceFood 每 Tick 都增加 Version，即使粮食没有变化，也会使 UI/存档签名持续变化。
- SimulationManager 仍为 0.02 秒 Tick、maximumTicksPerFrame=1000，对移动端偏激进。
- GameManager 仍强制 Application.runInBackground=true，不适合移动端默认行为。

二、不可违反的内容与数值规则
======================================================================

[N-001 普通资源无容量]
- 除 Food 外，ResourceState 不增加 Capacity。
- Resource ScriptableObject 不增加 MaxAmount。
- 不创建“木材仓库”“矿石仓库”等提高普通资源上限的核心机制。
- 不通过 UI、软上限或隐藏 Clamp 限制普通资源库存。
- 普通资源可以无限积累，ExpantaNum 负责表示。

[N-002 允许的非资源限制]
以下可以作为进度门槛，因为它们不是普通库存容量：
- 建筑价格等比增长。
- 科技前置。
- 加工链。
- 研究力。
- 人口与可用劳动力。
- 领土总量/已使用领土。
- 电力生产/消耗流量。
- 物流吞吐流量。
- 军事力量与补给流量。
- 一次性文明工程。
- 敌对星区强度。
- 食物容量。

[N-003 食物是唯一有容量的库存]
- FoodAmount <= FoodCapacity。
- Granary、Pottery、冷藏、轨道粮仓等只提高 FoodCapacity。
- 普通资源不受这些建筑影响。
- 食物不足必须产生游戏后果，不能只是数字归零。
- 在人口系统完成前，食物满足率至少影响人工建筑效率。
- 人口系统完成后，食物主要影响人口增长、健康、士气和可用劳动力。

[N-004 不制造死资源]
正式加入一个资源前必须至少满足：
- 有至少一个明确来源；
- 有至少两个用途，或一个高价值战略用途；
- 有可达的解锁路径；
- UI 有分类和说明；
- 存档和 ID 已覆盖；
- 自动测试验证来源/用途。

[N-005 研究必须产生意义]
每项研究至少满足一项：
- 解锁建筑；
- 解锁资源；
- 解锁系统；
- 提升生产倍率；
- 提升研究力；
- 提升建造效率；
- 增加领土；
- 提升军事或能源；
- 推进时代。
禁止大量仅作为“无效果前置节点”的研究。

[N-006 不复制猫国的仓储门槛]
可以借鉴：
- 资源链逐层出现；
- 科技解锁新系统；
- 早期资源在后期仍有用途；
- 不同系统形成乘法协同；
- 从聚落推进到太空的长期节奏。
不采用：
- 普通资源必须靠仓库提高上限才能购买下一项；
- 为了卡进度而给所有资源设置硬容量。

TODO C2-01：建筑材料成本改为等比增长
原因：
- 普通资源无上限；
- 当前线性成本会让后期生产建筑无限快速滚雪球；
- ExpantaNumExtensions 已有成熟的等比批量成本公式。

Building 增加：
[SerializeField] private ExpantaNum costGrowth = new ExpantaNum(1.15);
public ExpantaNum CostGrowth => costGrowth;

规则：
- 第 k 座单价 = baseCost × costGrowth^k。
- 一次购买 n 座使用 GeometricSeriesCost。
- Max 使用 MaxAffordableGeometricSeries。
- Space、劳动力、Food 等仍按实际数量线性计算。
- 自动建造必须使用同一 TryBuild。
- 拆除 n 座按“最后购买的 n 座”的等比成本计算 20% 返还。
- 不保存当前单价，加载后由 Amount 推导。

建议倍率：
- 原料建筑：1.12~1.14。
- 加工建筑：1.15~1.17。
- 研究/基础设施：1.18~1.20。
- 住房/人口容量：1.18~1.22。
- 奇观/时代工程：MaxCount=1，不用重复增长。

测试：
[ ] 买1、10、Max成本正确。
[ ] 多资源成本都按同一 owned/count 计算。
[ ] 资源不足原子失败。
[ ] 拆除最后 n 座返还正确。
[ ] 自动建造不绕过增长。
[ ] 超大 owned 值不逐座循环。

C8：外星战争
======================================================================

第一版采用确定性经营战争，不做即时战术。

状态：
- AttackPower；
- DefensePower；
- FleetPower；
- MilitaryManpower；
- SupplySatisfaction；
- CampaignProgress；
- Casualties；
- OccupiedTerritory。

建议公式：
CombatRatio = PlayerEffectivePower / EnemyPower

- ratio < 0.7：无法推进且持续损耗；
- 0.7~1.0：缓慢推进；
- 1.0~2.0：近似线性提升；
- >2.0：使用 Softcap，避免堆数值瞬间跳过全部内容。

胜利奖励：
- Territory；
- 新矿藏/资源来源；
- 外星科技样本；
- 新星区；
- 叙事事件。

要求：
- 战争消耗粮食、军需、能源和物流，但普通资源仍无容量。
- 战争失败不能随机清空整个存档。
- 结果可预测，UI 显示预计胜率/进度/消耗。
- 战斗逻辑不放入 UI。
